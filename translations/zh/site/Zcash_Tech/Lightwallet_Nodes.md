# Zcash 轻钱包节点

## TL;DR

* 大多数人通过轻钱包使用 Zcash，它不会下载整个区块链，而是与一台已经完成这项工作的服务器通信。
* 如今有两款软件为轻钱包提供服务：原始的、用 Go 编写的服务 **lightwalletd**，以及较新的、用 Rust 编写的索引器 **Zaino**。
* 你的密钥绝不会离开设备，服务器也无法花费你的资金或读取完全屏蔽交易中的金额和备注。
* 服务器最容易获知的是你的 IP 地址和活动时间——屏蔽交易保护的是区块链上发生的事情，而不是你与服务器之间的连接。
* Tor 可移除 IP 标识符；它可用于基于 `zcash_client_backend` 构建的钱包，在 ZODL 中则可于高级设置中启用。
* 你可以更换钱包所使用的服务器，或自行运行服务器——lightwalletd 和 Zaino 都是开源的。

## 核心说明

大多数人通过轻钱包使用 Zcash，它不会下载整个区块链，而是与一台已经完成这项工作的服务器通信。本页说明这些服务器是什么、它们能和不能了解你的哪些信息、如何通过 Tor 路由连接，以及如何更换钱包所使用的服务器。

如今有两款软件为轻钱包提供服务。**lightwalletd** 是原始服务，以 Go 编写。**Zaino** 是一个较新的 Rust 索引器，作为 zcashd 弃用工作的一部分构建。

### 轻钱包服务器的作用

轻钱包服务器位于你的钱包与 Zcash 区块链之间，为钱包提供高带宽效率的链上视图。它为你完成三件事。

它提供紧凑区块。它不会发送完整区块，而是发送精简形式，其中仅包含钱包检测向其屏蔽地址付款、检测其 notes 被花费，以及更新其见证所需的信息。

它转发你的交易。你发送交易时，钱包会将完成的交易交给服务器，再由服务器向网络广播。

它回答链上查询，例如当前区块高度以及钱包所需的手续费信息。

你的钱包仍会在本地完成私密工作。它持有你的密钥，对区块进行试解密以找到你的 notes，并在设备上构建和签署交易。

### 服务器能和不能看到什么

这部分很容易被误解。你的密钥不会离开设备，但这并不等于服务器无法获知你的任何信息。

这里的参考资料是 [Zcash 钱包应用威胁模型](https://zcash.readthedocs.io/en/latest/rtd_pages/wallet_threat_model.html)。如果你在意这些问题，值得完整阅读。它列出了多种对手类型。本页相关的是能够观察钱包与互联网之间、以及服务器与互联网之间流量的对手。运行服务器的人天然处于这一位置的一部分，因为你的钱包直接连接到他们。

先说受保护的内容。面对模型中的任何对手，包括已经攻破服务器的对手，对方“无法获知用户的任何密码学密钥材料（花费密钥、查看密钥、助记词等）”，无法窃取你的资金，也无法让你发送并非本意的资金。完全屏蔽交易中的金额和备注仍然经过加密。

接下来是未受保护的内容。威胁模型将以下内容列为面对流量观察型对手时的已知弱点：

| 弱点 | 方式 |
|:--|:--|
| 判断你是谁 | “对手知道用户的 IP 地址，这可能使其追溯到用户的真实身份” |
| 判断你的大致所在地 | 在“地理定位数据库中查询”你的 IP，以估计其位置 |
| 判断你是否以及何时发送或接收屏蔽交易 | 发送会“使用更多带宽；即使连接经过加密，这仍然可见”。模型指出，发送和接收这一行为本身对服务器可见 |
| 统计你一段时间内进行了多少笔交易 | 相同的带宽模式，只是观察时间更长 |
| 发现重复出现的付款模式 | 观察活动发生的时间 |
| 判断某个地址是否属于你 | 已经知道某地址的对手“可以向该地址发送资金，并观察你的钱包获取它时是否出现带宽峰值” |

该模型还指出，通常情况假定“用户与 lightwalletd 服务器运营者之间存在信任关系”。

因此，诚实的总结是：轻钱包服务器无法花费你的钱，也无法读取屏蔽交易中的金额或备注。它最容易获知的是你的 IP 地址和活动时间，而两者结合起来可能揭示许多关于个人的信息。屏蔽交易保护区块链上发生的事情，但它们本身并不会隐藏你与服务器之间的连接。

## 可视化 / 类比

想象一座收藏了所有已出版报纸的公共图书馆。全节点就像一名把整份档案带回家的读者。轻钱包则像一名向图书管理员索取每日摘要的读者——一张薄纸，仅包含足以判断是否有内容与自己相关的信息。

摘要是密封的：图书管理员在无法阅读哪些内容对你重要的情况下整理它，而你用自己的密钥在家中打开它。这就是紧凑区块，而打开它的过程就是设备上的试解密。

但图书管理员仍能看到哪位读者走进来、何时到来，以及带走的包裹有多厚。这就是 IP 地址和时间——无论信封密封得多好，从柜台都能看到。Tor 相当于派遣匿名快递员：图书管理员仍交付同一个包裹，却不再知道它被送往谁家。

## 深入探讨

### 通过 Tor 路由

Tor 切断了你的 IP 地址与钱包流量之间的关联，从而移除了上表中最强的标识符。

许多 Zcash 钱包所依赖的 Rust 库已提供此支持。zcash_client_backend 包含一个基于 Tor 的 Rust 实现 [Arti](https://tpo.pages.torproject.net/core/arti/) 构建的 Tor 模块，因此钱包无需附带单独的 Tor 客户端，即可通过 Tor 路由同步、交易广播和价格查询。

Zaino 开发者援引威胁模型直接提出了相同观点：需要“使用匿名传输协议（例如 Nym 或 Tor），以模糊 Zcash 索引服务器所见的客户端身份”。

在 **ZODL** 中，Tor 是高级设置中的一个选项。钱包的发布说明建议，如果用户“希望减少元数据暴露”，可使用手动连接模式“并在高级设置中启用 Tor”；应用也会在你恢复钱包前提示开启 Tor，而这正是新的 IP 地址原本可能与整段钱包历史关联的时刻。

有两点注意事项。Tor 会向服务器隐藏你的 IP，但不会改变服务器能从你发出的请求中获知的信息。而且洋葱路由会增加延迟，因此同步耗时更长。自行运行服务器以不同方式规避信任问题，因为运营者就是你自己。

### Zaino，Rust 索引器

[Zaino](/zcash-tech/zaino) 是由 Zingo 团队以 Rust 编写的索引器，旨在作为 zcashd 弃用工作的一部分替代 lightwalletd。它为轻客户端、全客户端和区块浏览器提供服务，读取“由 Zebra 或 Zcashd 全验证器持有”的链上数据。

它仍在积极开发中，0.8.0 版本于 2026 年 8 月发布。它旨在尽可能与 lightwalletd 保持向后兼容，因此钱包无需重写即可指向它。

Zaino 有单独的页面提供架构图，因此本页只介绍它作为轻钱包服务器的作用。

### 自行运行

最强的选择是成为自己的运营者，这会完全消除信任问题。两种服务器均为开源：[lightwalletd](https://github.com/zcash/lightwalletd) 以 Go 编写，[Zaino](https://github.com/zingolabs/zaino) 以 Rust 编写。两者都从全验证器读取数据，因此你还需要 [Zebra](/zcash-tech/zebra-full-node)。

## 常见错误

**认为服务器能够读取你的交易**。它不能。你的密钥留在设备上，完全屏蔽交易中的金额和备注仍然经过加密——即使面对已经攻破服务器的对手也是如此。

**把“屏蔽”理解为“匿名连接”**。屏蔽交易保护区块链上发生的事情。你的 IP 地址和活动时间属于另一层，而这恰恰是服务器能看到的层。

**假设 Tor 能消除所有痕迹**。Tor 会向服务器隐藏你的 IP，但不会改变服务器能从你发出的请求中获知的信息，并且会增加同步延迟。

**信任 wiki 页面上的服务器列表**。运营者会来去。在将钱包指向任何服务器之前，请查看 [hosh.zec.rocks](https://hosh.zec.rocks/zec)，确认哪些服务实际正在运行。

## 总结

轻钱包让你无需占用大量磁盘空间也能使用屏蔽池，这是一项不错的权衡。但要清楚自己在权衡什么。服务器无法拿走你的资金或读取你的屏蔽金额，但它很容易看到你的 IP 地址和交易时间。通过 Tor 路由，慎重选择运营者，或自行运行服务器。
