# Zcash ライトウォレットノード

## TL;DR

* ほとんどの人は、ブロックチェーン全体をダウンロードしないライトウォレットを通じて Zcash を利用しています。代わりに、その作業をすでに済ませたサーバーと通信します。
* 現在ライトウォレットを提供するソフトウェアは2つあります。Goで書かれた元祖サービスの **lightwalletd** と、Rustで書かれた新しいインデクサーである **Zaino** です。
* あなたの鍵がデバイスから外に出ることはなく、サーバーは資金を使うことも、完全にシールドされたトランザクション内の金額やメモを読むこともできません。
* サーバーが把握しやすいのはIPアドレスと活動のタイミングです。シールドされたトランザクションはブロックチェーン上で起きることを保護しますが、サーバーへの接続までは保護しません。
* TorはIP識別子を取り除きます。これは `zcash_client_backend` を基盤とするウォレットで利用でき、ZODLではAdvanced Settingsの設定項目です。
* ウォレットが使用するサーバーを変更したり、自分で運用したりできます。lightwalletd と Zaino はどちらもオープンソースです。

## 基本解説

ほとんどの人は、ブロックチェーン全体をダウンロードしないライトウォレットを通じて Zcash を利用しています。代わりに、その作業をすでに済ませたサーバーと通信します。このページでは、これらのサーバーが何であるか、サーバーがあなたについて見られるものと見られないもの、Tor経由で接続する方法、そしてウォレットが使用するサーバーを変更する方法を説明します。

現在ライトウォレットを提供するソフトウェアは2つあります。**lightwalletd** はGoで書かれた元祖サービスです。**Zaino** は、zcashd 廃止作業の一環として開発された、Rustで書かれた新しいインデクサーです。

### ライトウォレットサーバーの役割

ライトウォレットサーバーは、あなたのウォレットと Zcash ブロックチェーンの間に位置し、帯域幅効率の高いチェーンの表示を提供します。利用者のために、次の3つを行います。

コンパクトブロックを提供します。ブロック全体ではなく、ウォレットがシールドアドレスへの支払いを検出し、ノートの支出を検出し、witnessを更新するために必要なものだけを含むコンパクトな形式を送信します。

トランザクションを中継します。送金時、ウォレットは完成したトランザクションをサーバーに渡し、サーバーがネットワークにブロードキャストします。

現在のブロック高や、ウォレットが必要とする手数料情報など、チェーンへのクエリに回答します。

ウォレットは引き続き、プライベートな処理をローカルで行います。鍵を保持し、ブロックを試行復号してノートを見つけ、デバイス上でトランザクションを作成して署名します。

### サーバーが見られるものと見られないもの

ここは誤解されやすい部分です。鍵がデバイスから外に出ないことと、サーバーがあなたについて何も知り得ないことは同じではありません。

ここでの基準は、[Zcash ウォレットアプリの脅威モデル](https://zcash.readthedocs.io/en/latest/rtd_pages/wallet_threat_model.html)です。関心があるなら、全文を読む価値があります。そこでは数種類の攻撃者が定義されています。このページで重要なのは、あなたのウォレットとインターネットの間、およびサーバーとインターネットの間のトラフィックを監視できる攻撃者です。ウォレットは運営者のサーバーに直接接続するため、サーバーを運営する人は本質的にその立場の一部にいます。

まず、保護されるものから始めましょう。サーバーを侵害した攻撃者を含め、モデル内のすべての攻撃者に対して、攻撃者は「ユーザーの暗号鍵マテリアル（支出鍵、Viewing Key、シードフレーズなど）を一切学習できず」、資金を盗むことも、意図しない資金送信を強制することもできません。完全にシールドされたトランザクション内の金額とメモは暗号化されたままです。

一方、保護されないものもあります。脅威モデルでは、トラフィックを監視する攻撃者に対する既知の弱点として次を挙げています。

| 弱点 | 方法 |
|:--|:--|
| あなたが誰かを特定する | 「攻撃者はユーザーのIPアドレスを把握しており、そこからユーザーの実際の身元につながる可能性がある」 |
| おおよその所在地を特定する | IPアドレスを「地理位置情報データベースで検索し、所在地をおおよそ推定する」 |
| シールドされたトランザクションを送受信したか、およびその時刻を特定する | 送信では「より多くの帯域幅が使用され、接続が暗号化されていてもそれは見える」。モデルは、送受信という行為自体もサーバーから見えると指摘しています |
| 時間の経過とともに何件のトランザクションを行ったかを数える | より長期間にわたって観測される、同じ帯域幅パターン |
| 繰り返される支払いパターンを見つける | 活動がいつ起きるかを観測する |
| アドレスがあなたのものかを突き止める | すでにアドレスを知っている攻撃者は、「そのアドレスに資金を送信し、ウォレットがそれを取得する際に帯域幅の急増があるかどうかを見る」ことができる |

モデルはまた、通常のケースでは「ユーザーと lightwalletd サーバー運営者の間に信頼関係がある」ことを前提としていると指摘しています。

したがって、正直な要約はこうです。ライトウォレットサーバーはあなたのお金を使えず、シールドされたトランザクションの金額やメモも読めません。しかし、IPアドレスと活動のタイミングは把握しやすく、この2つを組み合わせると個人について多くのことが分かり得ます。シールドされたトランザクションはブロックチェーン上で起きることを保護します。それだけでは、サーバーへの接続を隠せません。

## ビジュアル / たとえ

これまでに印刷されたすべての新聞を保管する公共図書館を想像してください。フルノードは、アーカイブ全体を自宅に持ち帰る読者です。ライトウォレットは、司書に日ごとのダイジェストを頼む読者です。自分に関係する内容があるかを見つけるのに十分な情報だけを載せた、薄い紙です。

ダイジェストは封印されています。司書は、どの項目があなたにとって重要か読めないままそれをまとめ、あなたは自分の鍵で自宅にて開封します。これがコンパクトブロックであり、開封はデバイス上での試行復号です。

しかし司書には、どの読者が何時に来たか、どれくらい厚い束を持ち出したかは見えます。これがIPアドレスとタイミングです。封筒がどれほど厳重に封じられていても、受付から見えます。Torは匿名の配達人を送るのに相当します。司書は同じ束を渡しますが、それが誰の家に届くかは分かりません。

## 詳細解説

### Tor経由のルーティング

Torは、IPアドレスとウォレットのトラフィックの結びつきを断ち、上の表で最も強力な識別子を取り除きます。

多くの Zcash ウォレットが基盤とするRustライブラリには、この機能のサポートがあります。zcash_client_backend には、TorのRust実装である [Arti](https://tpo.pages.torproject.net/core/arti/) を基盤とするTorモジュールが含まれているため、別個のTorクライアントを同梱せずに、同期、トランザクションのブロードキャスト、価格検索をTor経由でルーティングできます。

Zaino の開発者も脅威モデルを直接引用して同じ主張をしています。そこには、「クライアントの身元を Zcash のインデックスサーバーから曖昧化するために、匿名トランスポートプロトコル（NymやTorなど）を使用する必要がある」とあります。

**ZODL** では、TorはAdvanced Settingsの設定項目です。ウォレットのリリースノートでは、メタデータ露出を減らしたい場合、ユーザーに「Advanced SettingsでTorを有効にする」ことに加えて手動接続モードを案内しています。また、通常なら新しいIPアドレスがウォレットの全履歴に結び付くことになる、ウォレット復元前のタイミングで、アプリはTorを有効にするよう提案します。

注意点が2つあります。TorはサーバーからIPアドレスを隠しますが、あなたが行うリクエストからサーバーが把握する内容を変えるわけではありません。また、オニオンルーティングはレイテンシーを追加するため、同期には時間がかかります。自分でサーバーを運用する場合は、運営者が自分自身になるため、信頼の問題を別の形で回避できます。

### Rustインデクサー、Zaino

[Zaino](/zcash-tech/zaino) は、ZingoチームがRustで書いたインデクサーで、zcashd 廃止作業の一環として lightwalletd を置き換えるために開発されました。ライトクライアント、フルクライアント、ブロックエクスプローラーにサービスを提供し、「Zebra または Zcashd のフルバリデータ」が保持するチェーンデータを読み取ります。

活発に開発されており、バージョン0.8.0は2026年8月にリリースされました。可能な限り lightwalletd との後方互換性を保つことを目標としているため、ウォレットは書き直すことなく接続先に指定できます。

Zaino にはアーキテクチャ図を備えた専用ページがあるため、このページではライトウォレットサーバーとしての役割だけを扱います。

### 自分で運用する

最も強力な選択肢は、自分自身が運営者になることです。これにより信頼の問題を完全に取り除けます。両方のサーバーはオープンソースです。Goで書かれた [lightwalletd](https://github.com/zcash/lightwalletd) と、Rustで書かれた [Zaino](https://github.com/zingolabs/zaino) です。どちらもフルバリデータから読み取るため、[Zebra](/zcash-tech/zebra-full-node) も必要になります。

## よくある誤解

**サーバーがあなたのトランザクションを読めると考えること**。読めません。鍵はデバイスに留まり、完全にシールドされたトランザクション内の金額とメモは、サーバーを侵害した攻撃者に対しても暗号化されたままです。

**「シールド」を「匿名接続」と解釈すること**。シールドされたトランザクションはブロックチェーン上で起きることを保護します。IPアドレスと活動のタイミングは別の層であり、まさにその層がサーバーから見えるものです。

**Torがすべての痕跡を消すと考えること**。TorはサーバーからIPアドレスを隠しますが、あなたが行うリクエストからサーバーが把握する内容を変えるわけではなく、同期にレイテンシーを追加します。

**Wikiページのサーバー一覧を信頼すること**。運営者は現れたり去ったりします。ウォレットの接続先を指定する前に、実際に何が稼働しているか [hosh.zec.rocks](https://hosh.zec.rocks/zec) で確認してください。

## まとめ

ライトウォレットでは、ディスク容量を使わずにシールドプールを利用できます。これは良いトレードオフです。ただし、何をトレードしているのかを明確に理解してください。サーバーは資金を奪えず、シールドされた金額も読めませんが、IPアドレスや取引のタイミングを把握しやすい立場にあります。Tor経由でルーティングする、運営者を意図的に選ぶ、または自分で運用してください。
