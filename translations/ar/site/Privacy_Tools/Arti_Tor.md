# **Arti: عميل Tor من الجيل التالي بلغة Rust**
![Atri Logo](/content-images/_unavailable.svg)

**Arti** هو مبادرة مشروع Tor لبناء عميل **Tor** من الجيل التالي باستخدام لغة البرمجة **Rust**. صُمّم Arti ليكون معياريًا وقابلًا للتضمين وجاهزًا للاستخدام في بيئات الإنتاج، إذ يقدّم تنفيذًا أكثر أمانًا وكفاءة لبروتوكولات إخفاء الهوية الخاصة بـ **Tor**. ومع **الإصدار 1.4.0 من Arti**، أُدخلت عدة تحديثات مهمة:

- **واجهة RPC جديدة** لتفاعل محسّن.
- أعمال تمهيدية لـ **دعم المرحّلات (relays)**.
- تحسينات في **مقاومة هجمات حجب الخدمة لخدمات onion من جهة الخدمة**.

يواصل هذا الإصدار جهود مشروع Tor لتوفير أمان وأداء ومعيارية أفضل لمستخدمي Tor والمطورين (developers).


---


## **تثبيت عميل Arti**

اتبع هذه الخطوات لتثبيت **Arti** وتشغيله كوكيل SOCKS على نظامك.

---

### **الخطوة 1: إعداد بيئة تطوير Rust**

قبل أن تتمكن من بناء Arti من الشيفرة المصدرية، يجب أن تكون قد ثبّتّ أحدث إصدار مستقر من **Rust**.

#### لتثبيت Rust:

1. تفضّل بزيارة [موقع Rust الرسمي](https://www.rust-lang.org/).
2. اتبع تعليمات التثبيت الخاصة بنظام التشغيل لديك.
3. تحقّق من التثبيت بتشغيل:
   
   ```sh
   rustc --version
   ```

سيؤكد هذا أن لديك أحدث إصدار مستقر من Rust مثبّتًا على نظامك.

#### **Note لمستخدمي Windows**:
- يمكن تثبيت Rust على Windows عبر [**rustup**](https://rustup.rs/)، وهو أداة لتثبيت سلسلة الأدوات (tools). تأكّد من أنك أعددت أيضًا بيئة بناء متوافقة (قد تحتاج إلى **Visual Studio Build Tools** على Windows).
  
---

### **الخطوة 2: استنساخ مستودع Arti**

للحصول على أحدث إصدار من عميل Arti، ستحتاج إلى استنساخ المستودع من [**GitLab**](https://gitlab.torproject.org/tpo/core/arti).

#### الخطوات:
1. افتح الطرفية (Command Prompt أو PowerShell أو Git Bash على Windows).
2. شغّل الأمر التالي لاستنساخ المستودع:
   
   ```sh
   git clone https://gitlab.torproject.org/tpo/core/arti.git
   ```
4. انتقل إلى المجلد *arti* الذي أُنشئ حديثًا:
   
   ```sh
   cd arti
   ```

سيؤدي هذا إلى جلب الشيفرة المصدرية لـ Arti إلى جهازك المحلي.

---

### **الخطوة 3: بناء الملف التنفيذي لـ Arti**

بعد استنساخ المستودع، تحتاج إلى بناء Arti باستخدام **Cargo**، وهو مدير الحزم وأداة البناء الخاصة بـ Rust.

#### لبناء Arti:
1. في الطرفية، شغّل الأمر التالي:
   ```sh
   cargo build --release
   ```

يقوم هذا الأمر بترجمة شيفرة Arti وتحسينها لبيئة الإنتاج (الخيار *--release*). سيُنشأ الملف التنفيذي في المجلد *target/release*.

#### موقع الملف التنفيذي المُترجَم:
- بعد البناء، سيكون الملف التنفيذي لـ Arti موجودًا في:  
  ```sh
  target/release/arti
  ```

يمكنك تشغيل هذا الملف التنفيذي مباشرة من الطرفية.

---

### **الخطوة 4: تشغيل وكيل SOCKS الخاص بـ Arti**

لاستخدام Arti كوكيل SOCKS (يوجّه حركة الإنترنت لديك عبر شبكة Tor)، تحتاج إلى تشغيل الوكيل.

#### لتشغيل وكيل SOCKS:
1. شغّل الأمر التالي:
   ```sh
   ./target/release/arti proxy -p 9150
   ```

يشغّل هذا الأمر Arti كـ **وكيل SOCKS5** على **المنفذ 9150**، وهو المنفذ الافتراضي الذي يستخدمه Tor لحركة SOCKS.

---

### **الخطوة 5: إعداد التطبيقات لاستخدام Arti**

بعد تشغيل Arti كوكيل SOCKS، تحتاج إلى إعداد تطبيقاتك لاستخدامه في توجيه الحركة عبر شبكة Tor.

#### الخطوات:
1. في إعدادات تطبيقك (مثل متصفح الويب أو تطبيق الطرفية)، ابحث عن **إعدادات الوكيل**.
2. اضبط **وكيل SOCKS5** على *localhost:9150*.

سيؤدي هذا إلى توجيه كل الحركة من تطبيقاتك عبر **شبكة Tor** باستخدام Arti وسيطًا.

---

## **تكامل Arti مع شبكة Tor**

إليك مخططًا مبسّطًا يوضح كيف يعمل Arti بالتنسيق مع شبكة Tor:


```plaintext
[Application] --(SOCKS5)--> [Arti SOCKS Proxy] --(Tor Protocol)--> [Tor Network]
```

- يتصل **التطبيق** بـ **وكيل Arti SOCKS** باستخدام بروتوكول **SOCKS5**.
- بعد ذلك يتواصل Arti مع **شبكة Tor**، مما يضمن إخفاء هوية حركتك أثناء مرورها عبر الشبكة.

## **مستودع GitLab والمساهمة**

إذا كنت مهتمًا بالمساهمة في تطوير **Arti**، فيمكنك استكشاف الشيفرة والمساهمة عبر **GitLab**.

- **رابط المستودع**: [مستودع Arti على GitLab](https://gitlab.torproject.org/tpo/core/arti)
- **استنساخ المستودع**:
  ```sh
  git clone https://gitlab.torproject.org/tpo/core/arti.git
  ```

### **التفريع والمساهمة**:
1. **أنشئ تفريعًا (Fork)** للمستودع على GitLab (يتطلب حسابًا على GitLab).
2. اربط مستودعك المُفرَّع بإعدادك المحلي:
   ```sh
   git remote add _name_ git@gitlab.torproject.org:_name_/arti.git
   git fetch _name_
   ```
   استبدل *_name_* باسم المستخدم الخاص بك على GitLab.

3. **ادفع التغييرات** إلى تفريعك:
   ```sh
   git push _name_ main
   ```

4. **أنشئ طلب دمج (Merge Request - MR)** على GitLab:
   انتقل إلى قسم Merge Request في تفريعك على GitLab:
   ```plaintext
   https://gitlab.torproject.org/_name_/arti/-/merge_requests
   ```

### **إرشادات طلبات الدمج**:
- **لا تُجرِ rebase ولا squash للالتزامات أثناء المراجعة**.
- عند الضرورة، استخدم *fixup!* أو *squash!* لدمج الالتزامات تلقائيًا.
- احرص على **إضافة التزامات جديدة** بدلًا من دمجها أثناء دورة المراجعة.

---

### **Notes إضافية**:

- **ملفات تنفيذية مبنية مسبقًا**: حتى الآن، لا يوفّر **Arti** ملفات تنفيذية رسمية مبنية مسبقًا. يجب عليك بناء العميل من الشيفرة المصدرية كما هو موضح أعلاه.
- **المعرفة بـ Rust**: إذا كنت تساهم في Arti، فلاحظ أن قاعدة الشيفرة لا تزال في طور التطور، وقد تحدث تغييرات أو إعادة هيكلة مع إضافة ميزات جديدة.
